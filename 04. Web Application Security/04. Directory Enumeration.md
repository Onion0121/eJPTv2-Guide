# Directory Enumeration

Directory enumeration is the process of discovering hidden directories, files, backup files, administrative panels, APIs, and other resources hosted on a web server. Since many sensitive resources are not linked from the main website, brute-forcing directories is one of the first steps during a web application penetration test.

Directory enumeration is heavily used during the **INE eJPT** exam and should be performed against every discovered web server.

---

# Why Directory Enumeration Matters

Developers often leave hidden resources accessible that are not visible from the website.

Examples include:

```
/admin

/login

/uploads

/images

/api

/dashboard

/config

/backup

/phpmyadmin

/dev

/test
```

Finding these resources can lead directly to:

- Authentication bypass
- Sensitive information disclosure
- File uploads
- Configuration leaks
- Remote Code Execution (RCE)
- SQL Injection
- Local File Inclusion (LFI)

# Directory Enumeration with Gobuster

Basic scan:

```bash
gobuster dir \
-u http://TARGET \
-w /usr/share/wordlists/dirb/common.txt
```

Example output:

```
/admin

/login

/images

/uploads

/dashboard
```

---

# Search for File Extensions

Many sensitive files have common extensions.

Example:

```bash
gobuster dir \
-u http://TARGET \
-w WORDLIST \
-x php,txt,bak,zip
```

Useful extensions:

```
php

asp

aspx

jsp

txt

bak

old

zip

tar

sql

conf

xml
```

---

# Ignore SSL Certificate Errors

```bash
gobuster dir \
-k \
-u https://TARGET \
-w WORDLIST
```

---

# Show Only Useful Responses

```bash
-s 200,301,302,403
```

Example:

```bash
gobuster dir \
-u http://TARGET \
-w WORDLIST \
-s 200,301,302,403
```

---

# Ignore Specific Status Codes

```bash
-b 404
```

Example:

```bash
gobuster dir \
-u http://TARGET \
-w WORDLIST \
-b 404
```

---

# Increase Threads

```bash
-t 50
```

Higher thread counts increase speed but also increase the likelihood of detection.

# Directory Enumeration with Wfuzz

Basic scan:

```bash
wfuzz \
--hc 404 \
-w WORDLIST \
http://TARGET/FUZZ
```

---

# Search PHP Files

```bash
wfuzz \
--hc 404 \
-w WORDLIST \
http://TARGET/FUZZ.php
```

---

# Filter by Response Length

Some applications always return HTTP 200.

Hide responses with the same size:

```bash
wfuzz \
--hh 1234 \
-w WORDLIST \
http://TARGET/FUZZ
```

# Feroxbuster

Feroxbuster performs recursive directory enumeration automatically.

Basic scan:

```bash
feroxbuster \
-u http://TARGET
```

Specify a wordlist:

```bash
feroxbuster \
-u http://TARGET \
-w WORDLIST
```

Advantages:

- Recursive scanning
- Multi-threaded
- Automatic discovery
- Fast

---

# FFUF

Fast web fuzzing:

```bash
ffuf \
-u http://TARGET/FUZZ \
-w WORDLIST
```

Hide 404 responses:

```bash
ffuf \
-u http://TARGET/FUZZ \
-w WORDLIST \
-fs 1234
```

---

# Dirsearch

Basic scan:

```bash
dirsearch \
-u http://TARGET
```

Specify extensions:

```bash
dirsearch \
-u http://TARGET \
-e php,txt,bak
```

# HTTP Status Codes

| Code | Meaning |
|------|---------|
| 200 | Resource exists |
| 204 | Empty response |
| 301 | Permanent redirect |
| 302 | Temporary redirect |
| 307 | Temporary redirect |
| 401 | Authentication required |
| 403 | Forbidden (resource exists) |
| 404 | Not found |
| 500 | Internal server error |

A **403 Forbidden** response is often just as valuable as a **200 OK**, as it confirms that the resource exists.

# Enumeration Strategy

Start with a small wordlist:

```bash
common.txt
```

If little is found:

```
↓

directory-list-2.3-small.txt

↓

directory-list-2.3-medium.txt

↓

SecLists
```

Always:

- Test file extensions.
- Test backup files.
- Enumerate discovered directories recursively.
- Review interesting HTTP responses.
- Repeat after authentication if login is available.

---

# Common Mistakes

Avoid these mistakes:

- Using only one wordlist.
- Ignoring 403 responses.
- Forgetting to search for backup files.
- Missing recursive enumeration.
- Ignoring robots.txt.
- Failing to test authenticated areas.
- Stopping after the first scan.

---

# eJPT Tips

During the **INE eJPT** exam:

- Enumerate every web server you discover.
- Start with **Gobuster** or **FFUF** for fast directory discovery.
- Use **Feroxbuster** for recursive enumeration when appropriate.
- Always search for common file extensions such as `.php`, `.bak`, `.txt`, `.zip`, and `.sql`.
- Check `robots.txt`, `sitemap.xml`, and hidden administrative panels.
- Follow up on every interesting directory with manual inspection using a browser or **Burp Suite**.
- Treat every `200`, `301`, `302`, and `403` response as potentially valuable.

# Cheat Sheet

```bash
# Gobuster
gobuster dir -u http://TARGET -w WORDLIST

# PHP files
gobuster dir -u http://TARGET -w WORDLIST -x php

# Multiple extensions
gobuster dir -u http://TARGET -w WORDLIST -x php,txt,bak,zip

# Ignore SSL
gobuster dir -k -u https://TARGET -w WORDLIST

# Show only useful responses
gobuster dir -u http://TARGET -w WORDLIST -s 200,301,302,403

# Ignore 404
gobuster dir -u http://TARGET -w WORDLIST -b 404

# Wfuzz
wfuzz --hc 404 -w WORDLIST http://TARGET/FUZZ

# PHP files with Wfuzz
wfuzz --hc 404 -w WORDLIST http://TARGET/FUZZ.php

# Feroxbuster
feroxbuster -u http://TARGET

# FFUF
ffuf -u http://TARGET/FUZZ -w WORDLIST

# Dirsearch
dirsearch -u http://TARGET

# View robots.txt
curl http://TARGET/robots.txt
```

# Summary

Directory enumeration is one of the most important phases of web application reconnaissance. By systematically discovering hidden directories, files, backup archives, administrative interfaces, and API endpoints, a penetration tester can significantly expand the attack surface of a target. Tools such as **Gobuster**, **Wfuzz**, **Feroxbuster**, **FFUF**, and **Dirsearch** complement each other and should be part of every web assessment. Mastering directory enumeration is essential for success in the **INE eJPT** exam and forms the foundation for identifying vulnerabilities and progressing to exploitation.
