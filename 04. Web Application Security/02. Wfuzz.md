# Wfuzz

Wfuzz is a flexible web fuzzing tool used to discover hidden directories, files, parameters, virtual hosts, authentication mechanisms, and vulnerabilities in web applications. Unlike Gobuster, which focuses mainly on directory brute-forcing, Wfuzz allows fuzzing almost any part of an HTTP request, making it an essential tool for web application penetration testing.

It is particularly useful during the **INE eJPT** exam for discovering hidden content, testing HTTP parameters, bypassing authentication, and identifying web application attack surfaces.

---

# Installation

Wfuzz comes pre-installed on Kali Linux.

Verify the installation:

```bash
wfuzz --version
```

Install manually:

```bash
sudo apt install wfuzz
```

Or using pip:

```bash
pip3 install wfuzz
```

---

# Basic Syntax

```bash
wfuzz [options] -w WORDLIST URL
```

The keyword **FUZZ** is replaced by each entry in the selected wordlist.

Example:

```bash
wfuzz \
-w /usr/share/wordlists/dirb/common.txt \
http://TARGET/FUZZ
```

---

# Understanding FUZZ

The keyword **FUZZ** tells Wfuzz where to inject payloads.

Example:

```
http://TARGET/FUZZ
```

Generated requests:

```
http://TARGET/admin

http://TARGET/login

http://TARGET/images

http://TARGET/uploads
```

# Hide 404 Responses

Most responses will return **404 Not Found**.

Hide them:

```bash
wfuzz \
--hc 404 \
-w WORDLIST \
http://TARGET/FUZZ
```

---

# Show Only Specific Status Codes

Example:

```bash
wfuzz \
--sc 200 \
-w WORDLIST \
http://TARGET/FUZZ
```

Useful values:

```

302

403

401
```

# Filter by Response Length

Hide responses with a specific size:

```bash
wfuzz \
--hh 1234 \
-w WORDLIST \
http://TARGET/FUZZ
```

Useful when every request returns **HTTP 200** but error pages always have the same size.

# Parameter Fuzzing

Suppose the application uses:

```
http://TARGET/index.php?id=1
```

Replace the value:

```bash
wfuzz \
-w WORDLIST \
"http://TARGET/index.php?id=FUZZ"
```

Useful for finding:

- SQL Injection
- LFI
- Authentication bypass
- Hidden IDs

---

# POST Parameter Fuzzing

Example:

```bash
wfuzz \
-w WORDLIST \
-d "username=admin&password=FUZZ" \

```

# Useful Filters

| Option | Description |
|---------|-------------|
| --hc | Hide status codes |
| --sc | Show status codes |
| --hh | Hide response size |
| --hw | Hide word count |
| --hl | Hide line count |
| --hc 404 | Hide 404 pages |
| --sc 200 | Show only 200 responses |

# Typical eJPT Workflow

Start with directory enumeration:

```bash
wfuzz \
--hc 404 \
-w common.txt \
http://TARGET/FUZZ
```

If a login page is found:

- Enumerate parameters.
- Test default credentials.
- Brute-force usernames (if permitted).
- Brute-force passwords (if permitted).

If an application accepts user input:

- Fuzz parameters.
- Test for SQL Injection.
- Test for Local File Inclusion.
- Test hidden endpoints.

# Wfuzz vs Gobuster

| Feature | Wfuzz | Gobuster |
|----------|--------|-----------|
| Directory Enumeration | ✅ | ✅ |
| Parameter Fuzzing | ✅ | ❌ |
| POST Requests | ✅ | ❌ |
| Cookies | ✅ | Limited |
| Custom Headers | ✅ | ✅ |
| Authentication Testing | ✅ | Limited |
| Virtual Hosts | ✅ | ✅ |
| DNS Enumeration | ❌ | ✅ |
| Response Filtering | Excellent | Good |

Both tools complement each other and are commonly used together during penetration tests.

---

# Common Mistakes

Avoid these mistakes:

- Forgetting to filter 404 responses.
- Ignoring response size differences.
- Using only one wordlist.
- Forgetting to fuzz POST parameters.
- Missing authenticated areas.
- Ignoring redirects.
- Not testing virtual hosts.

---

# eJPT Tips

During the **INE eJPT** exam:

- Use Wfuzz when Gobuster cannot identify interesting resources.
- Filter responses by status code, size, lines, or words to reduce noise.
- Fuzz GET and POST parameters for hidden functionality.
- Test authenticated areas using cookies.
- Enumerate virtual hosts if multiple websites may exist on the same server.
- Pair Wfuzz with **Gobuster**, **Burp Suite**, **Nikto**, and **SQLmap** for comprehensive web application assessment.

# Cheat Sheet

```bash
# Directory enumeration
wfuzz --hc 404 -w WORDLIST http://TARGET/FUZZ

# Show only HTTP 200
wfuzz --sc 200 -w WORDLIST http://TARGET/FUZZ

# Hide response length
wfuzz --hh 1234 -w WORDLIST http://TARGET/FUZZ

# Hide line count
wfuzz --hl 50 -w WORDLIST http://TARGET/FUZZ

# Hide word count
wfuzz --hw 120 -w WORDLIST http://TARGET/FUZZ

# Parameter fuzzing
wfuzz -w WORDLIST "http://TARGET/index.php?id=FUZZ"

# POST request
wfuzz -w passwords.txt -d "username=admin&password=FUZZ" http://TARGET/login.php

# File enumeration
wfuzz -w WORDLIST http://TARGET/FUZZ.php

# Virtual host enumeration
wfuzz -H "Host: FUZZ.target.com" -w WORDLIST http://TARGET

# Custom header
wfuzz -H "Authorization: Bearer TOKEN" -w WORDLIST http://TARGET/FUZZ

# Cookie authentication
wfuzz -H "Cookie: PHPSESSID=value" -w WORDLIST http://TARGET/FUZZ

# Save results
wfuzz -f results.txt -w WORDLIST http://TARGET/FUZZ
```

# Summary

Wfuzz is one of the most versatile web fuzzing tools available, allowing penetration testers to enumerate directories, discover hidden parameters, brute-force login forms, test virtual hosts, and analyze HTTP responses with powerful filtering options. While Gobuster excels at fast content discovery, Wfuzz provides much greater flexibility for interacting with web applications. Mastering Wfuzz will significantly improve your web enumeration methodology and is a valuable skill for the **INE eJPT** exam and future web application penetration testing engagements.
