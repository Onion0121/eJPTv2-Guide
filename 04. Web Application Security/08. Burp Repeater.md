# Burp Repeater

Burp Repeater is one of the most useful modules in Burp Suite. It allows you to manually resend, modify, and analyze HTTP requests as many times as necessary without having to interact with the web application again. It is an essential tool for testing parameters, authentication, SQL Injection, Local File Inclusion (LFI), command injection, IDOR, and many other web vulnerabilities.

Unlike Intruder, Repeater is designed for **manual testing**, giving the penetration tester complete control over every request.

---

# What is Burp Repeater?

Burp Repeater allows you to:

- Replay HTTP requests
- Modify parameters
- Edit headers
- Change cookies
- Test authentication
- Analyze responses
- Compare different payloads
- Confirm vulnerabilities manually

# Why Use Repeater?

Repeater is perfect when you want to test:

- SQL Injection
- Local File Inclusion
- Command Injection
- Authentication Bypass
- Session Management
- Cookie Manipulation
- Access Control
- Parameter Tampering

Instead of browsing repeatedly, you simply edit and resend the request.

# Sending Requests to Repeater

Capture a request in Proxy.

Right-click:

```
Send to Repeater
```

Or use:

```
Ctrl + R
```

Open:

```
Repeater Tab
```

The request is now ready for testing.

---

# Repeater Interface

The window contains:

```
Request

↓

Send Button

↓

Response
```

Every time you press **Send**, Burp sends the modified request to the server.

---

# Basic Example

Captured request:

```http
GET /profile?id=5 HTTP/1.1

Host: target.local
```

Modify:

```http
GET /profile?id=1 HTTP/1.1

Host: target.local
```

Click:

```
Send
```

Observe the response.


# SQL Injection Testing

Original:

```
id=5
```

Test:

```
id=5'

id=5--

id=5 OR 1=1

id=5 UNION SELECT NULL

id=5 AND 1=2
```

Observe:

- Error messages
- Different page sizes
- Response delays
- HTTP status codes

---

# Local File Inclusion (LFI)

Original:

```
?page=home.php
```

Modify:

```
?page=../../../../etc/passwd
```

Or:

```
?page=../../../../windows/win.ini
```

Send and inspect the response.

---

# Command Injection

Original:

```
host=127.0.0.1
```

Test:

Linux:

```
127.0.0.1;id

127.0.0.1&&whoami

127.0.0.1|hostname
```

Windows:

```
127.0.0.1&whoami

127.0.0.1&&hostname
```

---

# Common Mistakes

Avoid these mistakes:

- Changing multiple parameters at once.
- Ignoring HTTP response headers.
- Looking only at status codes.
- Forgetting cookies.
- Not testing both GET and POST requests.
- Failing to compare response sizes and response times.

---

# eJPT Tips

During the **INE eJPT** exam:

- Send every interesting request to Repeater.
- Test one parameter at a time.
- Compare responses carefully.
- Modify cookies and hidden fields.
- Test for SQL Injection, LFI, command injection, and IDOR manually.
- Observe status codes, response length, and server behavior.
- Use Repeater before launching automated attacks with Intruder.

# Summary

Burp Repeater is the primary module for manual web application testing. It allows penetration testers to modify and replay HTTP requests repeatedly, making it ideal for validating vulnerabilities such as SQL Injection, Local File Inclusion, Command Injection, IDOR, authentication flaws, and session management issues. By carefully comparing server responses after changing one parameter at a time, testers can accurately identify and confirm security weaknesses. Mastering Burp Repeater is an essential skill for both real-world web assessments and the **INE eJPT** certification exam.
